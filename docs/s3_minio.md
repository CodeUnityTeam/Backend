# Хранилище S3 (MinIO)

В проекте используется объектное хранилище S3 (на базе MinIO) для хранения всех медиафайлов: аватаров, изображений к вопросам, ответам и формам обратной связи.

### Архитектура и сервис
Для взаимодействия с S3 реализован универсальный транспортный сервис `MinioService` (`core/s3_utils.py`). Он автоматически:
- Создает бакеты (`avatars`, `images`), если они отсутствуют.
- Применяет политики публичного чтения (Public Read) для доступа к файлам по прямым ссылкам.
- Выполняет загрузку и удаление объектов.

### Общий флоу работы с изображениями
Для минимизации нагрузки на основную БД используется двухэтапная загрузка:
1. **Upload**: Файл загружается через `POST /api/v1/qna/files/upload/`. Сервис возвращает публичный `image_url` и метаданные (имя, размер, тип).
2. **Attach**: Полученные данные передаются фронтендом в основные эндпоинты (создание вопроса, профиля и т.д.). В базе сохраняются только метаданные и ссылка.

### Автоматическое управление файлами
Для поддержания чистоты хранилища реализована автоматизация удаления:
- **Сигналы (`post_delete`)**: При удалении записи из БД (даже каскадном), физический файл автоматически удаляется из MinIO.
- **Транзакционность**: Удаление файлов происходит только после успешного коммита транзакции в БД (`transaction.on_commit`).
- **Замена файлов**: При обновлении (`PATCH`) изображения старые файлы удаляются, освобождая место.

### Доступ к хранилищу (Локально)
- **API**: `http://localhost:9000`
- **Консоль управления**: `http://localhost:9001` (логин/пароль в `.env`)
